1. 内核态与用户态

CPU 有两种运行状态：内核态（管态 / 核心态）与用户态（目态）。区分状态的目的是保护操作系统，防止用户程序执行危险指令、破坏系统内核。

定义

内核态：可执行特权指令，可访问所有寄存器和全部存储空间，操作系统内核运行在此状态。
用户态：只能执行非特权指令，只能访问自己的地址空间，用户程序运行在此状态。

关键结论：两种状态如何切换（高频）

用户态 → 内核态：只能由中断或异常（含系统调用引起的陷入 trap）触发，由硬件自动完成，是一条隐指令，不是特权指令。
内核态 → 用户态：由操作系统执行一条特权指令，修改程序状态字寄存器 PSW 的标志位完成。

1.1 特权指令与非特权指令

类型含义典型举例
特权指令 不允许用户程序使用，只能在内核态执行 I/O 指令、开/关中断、清内存、置时钟、修改 PSW、设置中断屏蔽字
非特权指令 用户程序可执行的一般指令 算术/逻辑运算、取数、访存、转移指令，以及陷入指令 trap
易错点

判断一条指令是否「特权」，看它是否可能危及系统安全。特别注意：陷入指令（trap / 访管指令）不是特权指令——系统调用恰恰需要用户在用户态下主动发起。

2. 中断与异常

关键结论

中断（含异常）是让操作系统内核夺回 CPU 使用权的唯一途径，也是「用户态 → 内核态」转换的根本机制。

类别来源与当前指令的关系举例
外中断（中断） CPU 外部 无关 时钟中断、I/O 完成中断、键盘输入
内中断（异常） CPU 内部 有关 非法操作码、地址越界、算术溢出、缺页、陷入（trap）
记忆口诀

「外时钟、内异常」：与当前指令无关、来自 CPU 外部的称中断；与当前指令有关、来自 CPU 内部的称异常。外中断又可分为可屏蔽中断与不可屏蔽中断。

2.1 中断处理过程

中断响应由硬件与软件配合完成，其中硬件自动完成的部分称为中断隐指令（并非指令系统中真正的指令）：

  1. 关中断：硬件自动关闭中断，保证后续保存现场不被新中断打断；
  2. 保存断点：把原程序的下一条指令地址（PC）保存到栈或指定单元；
  3. 形成中断服务程序入口地址：硬件将中断向量送入 PC，转去执行中断服务程序。
易错点

「保存断点」「关中断」「形成中断服务程序入口」由硬件自动完成（中断隐指令）；「保存现场（通用寄存器）」由中断服务程序（软件）完成，不要混淆。

3. 系统调用

定义

系统调用是操作系统提供给应用程序（程序员）使用的接口，是应用程序请求操作系统内核服务的桥梁，属于程序接口（而非命令接口）。

3.1 系统调用的执行过程

  1. 传递参数：用户程序把系统调用所需的参数放入寄存器或内存（栈）中；
  2. 执行陷入指令（trap）：在用户态执行陷入指令，产生内部中断，CPU 由用户态转为内核态；
  3. 执行系统调用服务程序：CPU 在内核态执行相应的内核服务程序，完成具体功能；
  4. 返回用户态：内核执行一条特权指令（修改 PSW），使 CPU 回到用户态，并把结果返回给用户程序。
关键结论

① 系统调用的服务程序一定运行在内核态；② 发起系统调用的陷入指令运行在用户态；③ 一次系统调用包含「用户态 → 内核态 → 用户态」的完整转换。

3.2 系统调用与库函数的区别

对比项系统调用库函数
提供者操作系统内核语言（如 C 标准库）或第三方
运行状态内核态用户态
与内核关系直接请求内核服务有的封装了系统调用，有的完全不涉及
举例read、write、fork、openprintf（底层封装 write）、sqrt（不涉及）
易错点

并非所有库函数都会引起系统调用。例如 printf 底层可能调用 write，但 sqrt、abs 等数学函数只是普通计算，不需要系统调用、不进入内核态。

4. 内核与程序的运行环境

内核与运行环境

内核（含时钟管理、中断处理、原语等）运行在内核态，用户程序运行在用户态；用户程序通过系统调用请求内核服务，内核通过中断/异常夺回 CPU 控制权。

5. 本节小结与真题问法

记忆口诀

两态：内核态、用户态。
转换：用→核靠中断/异常（硬件自动），核→用靠特权指令（改 PSW）。
中断：外中断与当前指令无关，内中断（异常）与当前指令有关。
系统调用四步：传参 → 陷入指令 → 内核态服务程序 → 返回用户态。

真题典型问法

① 问「CPU 从用户态转为内核态的原因」→ 答发生了中断或异常（含系统调用陷入）。
② 问「用户态到内核态的转换由什么完成」→ 由硬件完成（中断隐指令），不是特权指令。

③ 给一串指令判断哪些是特权指令 → 「I/O、置时钟、改 PSW、关中断」是特权，trap 不是。
④ 问「系统调用与库函数的关系」→ 系统调用在内核态；库函数在用户态，不一定涉及系统调用。

教材原文（王道）

系统调用是操作系统提供给应用程序使用的接口，是应用程序请求操作系统内核服务的桥梁；用户程序在用户态下执行陷入指令（trap），由此引起一个内部中断，使 CPU 由用户态进入内核态。
