1. 为什么需要虚拟机

传统计算机中，一台物理机器通常只安装并运行一个操作系统，硬件资源难以在同一时间被多套系统共享。虚拟化技术通过把一台物理计算机「切分」成多台相互隔离的逻辑计算机，突破了「一机一系统」的限制。

它带来两个核心价值：资源复用（提高硬件利用率）与环境隔离（一台虚拟机出问题通常不牵连其他）。

定义

虚拟机（Virtual Machine, VM）是指通过虚拟化技术，在一台物理计算机上虚拟出的、具有完整硬件系统功能、运行在完全隔离环境中的逻辑计算机。每台虚拟机都拥有自己独立的虚拟硬件（虚拟 CPU、虚拟内存、虚拟外设），并可独立安装、运行各自的操作系统。

2. 虚拟机管理程序（VMM）

让多台虚拟机共存而不互相干扰的关键部件，是虚拟机管理程序。

核心概念

虚拟机管理程序（Virtual Machine Monitor, VMM），又称 Hypervisor，是位于物理硬件与虚拟机之间、负责资源抽象与分配的软件层。它把物理资源（CPU、内存、I/O）抽象、切分并分配给上层各虚拟机，同时保证各虚拟机之间彼此隔离。

按 VMM 所处的位置，可将它分为两类——这是本节的核心考点。

2.1 第一类虚拟机管理程序（裸金属型，Type-1）

  • 运行位置：直接运行在裸机硬件之上，不依赖任何宿主操作系统，本质上相当于一个操作系统。
  • 特权级：运行在最高特权级，直接控制硬件资源并把它分配给各虚拟机。
  • 典型产品：Xen、VMware ESXi、Microsoft Hyper-V 等。

2.2 第二类虚拟机管理程序（宿主型，Type-2）

  • 运行位置：运行在宿主操作系统之上，是宿主 OS 上的一个应用程序。
  • 特权级：借助宿主操作系统来管理硬件，自身并不直接掌控硬件。
  • 典型产品：VMware Workstation、VirtualBox 等桌面虚拟化软件。
对比项第一类（裸金属型）第二类（宿主型）
运行位置直接在裸机硬件之上在宿主操作系统之上
是否依赖宿主 OS不依赖，本身即相当于 OS依赖，是宿主 OS 上的应用程序
典型产品Xen、VMware ESXi、Hyper-VVMware Workstation、VirtualBox
性能更接近物理机，开销较小多经一层宿主 OS，开销相对大
典型场景服务器、数据中心个人桌面、学习实验
关键结论

判断第一类还是第二类，只需问一句：VMM 是「直接站在硬件上」，还是「站在宿主操作系统上」。前者是第一类，后者是第二类。

3. 虚拟化原理

VMM 通过「抽象 + 分配 + 隔离」实现虚拟化：

  1. 抽象：把物理 CPU、内存、外设等资源抽象成可被多个虚拟机共享的资源池。
  2. 分配：按需把资源切分给各虚拟机，使每台虚拟机都「看到」一套完整的虚拟硬件。
  3. 隔离：各虚拟机运行在各自独立的环境中，互不可见、互不干扰。
一句话理解

VMM 就像「硬件的总调度员」：把一份物理资源切成多份虚拟资源分给每个虚拟机，并保证谁也不越界。

4. 虚拟机的优点与局限

维度说明
优点：隔离性好各虚拟机彼此独立，一台崩溃通常不影响其他虚拟机与宿主系统。
优点：资源复用一台物理机可同时运行多套不同操作系统，提高硬件利用率。
优点：易封装迁移虚拟机以文件形式封装，便于复制、快照与回滚，适合做实验。
局限：性能开销虚拟化会带来额外开销，第二类 VMM 因多一层宿主 OS 尤为明显。
局限：依赖硬件、管理复杂高效虚拟化通常需要 CPU 提供硬件虚拟化支持，规模化管理成本较高。
易错点

虚拟机能提高资源利用率与隔离性，但并非没有性能开销。凡宣称「虚拟机与物理机性能完全相同」「不需要任何硬件支持即可高效运行」的说法均错误。

5. 小结与真题问法

记忆口诀

一个部件：VMM（Hypervisor）。

两大类：第一类——站硬件上（裸金属，Xen/ESXi）；第二类——站宿主 OS 上（宿主型，Workstation/VirtualBox）。

三步原理：抽象 → 分配 → 隔离。

真题典型问法

① 给出一组虚拟化产品，问「哪些属于第一类/第二类 VMM」→ 看它在硬件上还是在宿主 OS 上。

② 问「第一类与第二类的区别」→ 从运行位置、是否依赖宿主 OS、性能三方面作答。

③ 判断关于虚拟机优缺点的说法 → 常见错误是「无性能开销」「不依赖硬件」「不需要隔离」。

教材原文（王道）

虚拟机管理程序（VMM）又称 Hypervisor，是运行在物理硬件与虚拟机之间的软件层，负责将物理资源抽象、分配并隔离给上层的一台或多台虚拟机。
