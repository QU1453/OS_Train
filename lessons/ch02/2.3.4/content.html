2.3.4 用信号量实现进程同步与互斥

掌握了信号量及 P、V 原语之后，本节把二者组合起来，解决实际的同步与互斥问题。解决这类问题的核心，在于先弄清进程/操作之间的关系，再据此设置信号量。这也是 408 中「用 PV 操作描述前趋关系」「生产者-消费者」等题型的通用解题框架。

1. 分析同步互斥问题的一般步骤

  1. 关系分析：找出题目中各个进程（或操作）之间存在哪些同步（前趋）关系和互斥关系。同步关系表现为「谁必须在谁之前」，互斥关系表现为「谁和谁不能同时访问同一临界资源」。
  2. 整理思路：根据同步、互斥关系，确定需要设置哪几个信号量，并直接写出对应的 P、V 操作位置。
  3. 设置信号量：互斥信号量初值为 1，同步信号量（用于前趋）初值为 0。最后检查 P、V 是否配对、顺序是否正确。
记忆口诀

互斥：mutex 初值 1，同一进程内「进入区 P、退出区 V」。
同步：信号量初值 0，「先做的 V、后做的 P」，跨进程配对。

2. 用信号量实现互斥（分析要点）

若多个进程竞争同一临界资源，则设置一个初值为 1 的互斥信号量 mutex，把对临界资源的访问包在 P(mutex)…V(mutex) 之间：

semaphore mutex = 1;    // 互斥信号量，初值 1

P1() {
    ...
    P(mutex);           // 进入区
    // 访问临界资源（临界区）
    V(mutex);           // 退出区
    ...
}

要点：① 不同的临界资源要用不同的 mutex；② 同一进程内 P、V 成对；③ 临界区代码尽量短。这些在上节已详尽讨论，此处不再展开。

3. 用信号量实现同步：前趋图

3.1 前趋图与设置方法

定义

前趋图（Precedence Graph）是一个有向无环图（DAG），图中的每个结点表示一个进程、程序段或一条语句，每条有向边表示两结点之间的前趋关系：若存在边 Si → Sj，则 Si 必须在 Sj 开始之前完成。

关键结论：前趋图 → 信号量的映射规则

① 每一条前趋边设置一个信号量，初值为 0；
② 在这条边起点的操作完成之后执行 V（通知后继可以开始）；
③ 在这条边终点的操作开始之前执行 P（等待前趋完成）；
④ 若一个操作有多条入边，则它开始前要对所有入边对应的信号量都做 P；若有多条出边，则它完成后要对所有出边对应的信号量都做 V。

3.2 例：四语句的前趋关系

设四条语句 S1、S2、S3、S4 满足前趋关系：S1→S2、S1→S3、S2→S4、S3→S4。共有四条边，故设置四个初值为 0 的信号量 a、b、c、d：

semaphore a = 0, b = 0, c = 0, d = 0;

S1() { // 出边 a(S1→S2)、b(S1→S3)
    ...
    V(a); V(b);          // S1 完成后，通知 S2、S3
}
S2() { // 入边 a，出边 c(S2→S4)
    P(a);                // 等 S1
    ...
    V(c);                // 通知 S4
}
S3() { // 入边 b，出边 d(S3→S4)
    P(b);                // 等 S1
    ...
    V(d);                // 通知 S4
}
S4() { // 入边 c、d
    P(c); P(d);          // 等 S2 和 S3 都完成
    ...
}

按此规则写出的 P、V 序列，天然保证了「先做的先 V、后做的后 P」，也就保证了各结点严格按照前趋图规定的次序执行。

4. 单缓冲区的生产者-消费者问题

这是「同步 + 互斥」综合应用的经典模型，也是后续 2.3.5 节的基础。

4.1 问题描述与关系分析

设有一个大小为 1 的缓冲区，生产者进程不断把产品放入缓冲区，消费者进程不断从缓冲区取出产品。分析两类关系：

  • 同步关系（前趋）：生产者放入产品后，消费者才能取（先生产后消费）；消费者取走产品后，生产者才能再放（先消费后生产）。
  • 互斥关系：缓冲区是临界资源，同一时刻只能有一个进程对其读写。

据此设置三个信号量：

信号量含义初值类型
empty空闲缓冲区的数量1同步（资源信号量）
full已放入产品的数量0同步（资源信号量）
mutex缓冲区的互斥访问1互斥

4.2 PV 操作描述

semaphore empty = 1;    // 空闲缓冲区数（初值 = 缓冲区容量）
semaphore full  = 0;    // 产品数
semaphore mutex = 1;    // 缓冲区互斥

producer() {
    while (true) {
        produce an item;           // 生产一个产品
        P(empty);                  // ① 申请一个空槽（同步：缓冲满则等待）
        P(mutex);                  // ② 申请缓冲区的互斥访问
        put item into buffer;      // ③ 临界区：放入产品
        V(mutex);                  // ④ 释放缓冲区
        V(full);                   // ⑤ 通知消费者：产品数 +1
    }
}

consumer() {
    while (true) {
        P(full);                   // ① 申请一个产品（同步：缓冲空则等待）
        P(mutex);                  // ② 申请缓冲区的互斥访问
        take item from buffer;     // ③ 临界区：取走产品
        V(mutex);                  // ④ 释放缓冲区
        V(empty);                  // ⑤ 通知生产者：空槽 +1
        consume the item;          // 消费产品
    }
}
关键结论：P 操作的顺序——先同步，后互斥

对资源信号量（empty/full）的 P 操作必须写在对互斥信号量 mutex 的 P 操作之前。即「先申请资源、再申请临界区锁」。V 操作的先后顺序则没有严格要求。

易错点：交换 P(empty) 与 P(mutex) 会死锁

若生产者写成「先 P(mutex) 再 P(empty)」：当缓冲区已满（empty = 0）时，生产者先拿到了 mutex（锁住了缓冲区），随后在 P(empty) 上阻塞；此时消费者想取产品，必须先 P(full) 成功、再 P(mutex)，但 mutex 已被生产者占用，消费者同样阻塞——生产者等空槽、消费者等锁，互相等待，形成死锁。可见同步信号量的 P 操作在先，是为了避免「持锁等待」。

易错点：缓冲区大小与初值

empty 的初值等于缓冲区容量（本题为 1）；full 的初值为 0；mutex 初值为 1。即便有多个生产者、多个消费者，mutex 仍为 1（缓冲区整体作为同一个临界资源）。不要因为「进程多」而把 mutex 初值调大。

5. 本节小结与真题问法

真题典型问法

① 给出前趋图，要求写出各进程的 P、V 操作 → 按「每条边一个信号量、初值 0；起点 V、终点 P」直接套用。
② 生产者-消费者问题中，问「哪个信号量初值为多少」→ empty=容量、full=0、mutex=1。
③ 问「把 P(empty) 与 P(mutex) 交换顺序会怎样」→ 可能引起死锁（持锁等待）。
④ 问「V 操作顺序能否交换」→ 一般可以交换，但 P 操作顺序不能随意交换。
⑤ 综合题要求「用信号量描述某场景」→ 先做关系分析，再分别处理同步（初值 0）与互斥（初值 1）。

记忆口诀

三步走：关系分析 → 确定信号量 → 写 P、V。
初值：互斥为 1，同步为 0。
顺序：P 先同步后互斥，V 顺序较随意。
前趋图：边即信号量，初值为 0，起 V 终 P。

教材原文（王道）

用信号量实现进程同步：若要求某操作在前，另一操作在后，则前者执行后执行 V 操作，后者执行前执行 P 操作，同步信号量初值为 0。生产者-消费者问题中，生产者申请空缓冲区（P(empty)）必须在申请缓冲区互斥信号量（P(mutex)）之前，否则可能造成死锁。
