1. 调度算法的分类

进程调度的核心任务是从就绪队列中按某种策略选择一个进程，把 CPU 分配给它。按「是否允许抢占」，调度算法分为两类：

定义

非抢占式（非剥夺式）：一旦把 CPU 分配给某进程，就让它一直运行到完成或主动阻塞，中途绝不因「来了更合适的进程」而收回 CPU。
抢占式（剥夺式）：正在运行的进程可被优先级更高或更紧迫的进程剥夺 CPU，被剥夺者回到就绪队列。

本节介绍六种经典算法：FCFS、SJF/SPF、HRRN、优先级调度、时间片轮转、多级反馈队列。

2. 先来先服务 FCFS

FCFS（First Come First Served）：按进程进入就绪队列的先后次序（等价地，按作业到达的先后）依次调度，非抢占式。谁先到，谁先服务。

  • 优点：公平、实现简单，不会使进程长期得不到服务（不会饥饿）。
  • 缺点：对短作业不利。若一个长作业先到，后面大量短作业都要排在它后面等待，导致平均周转时间、平均带权周转时间偏大（出现「护航效应」）。
关键结论

FCFS 有利于 CPU 繁忙型作业，不利于 I/O 繁忙型作业，也不利于短作业。它是非抢占式，且「排队顺序 = 到达顺序」。

3. 短作业优先 SJF / SPF

SJF（Shortest Job First），又叫短进程优先 SPF：每次从就绪队列中选择运行时间最短的作业（进程）投入运行。做题时注意区分两种版本：

版本规则
非抢占式 SJF当前进程运行期间，即使来了更短的作业，也不打断；只有当当前进程完成（或阻塞）后，才在当前已到达的作业中选最短者。
抢占式 SJF（又称 SRTN，最短剩余时间优先）每当有新作业到达，就比较「新作业的服务时间」与「当前进程的剩余运行时间」，若新作业更短，则立即抢占 CPU。
  • 优点：在所有作业同时到达（且不考虑抢占）时，SJF 能得到最小的平均等待时间和平均周转时间，是理论上最优的非抢占算法。
  • 缺点：对长作业不利，可能导致长作业长期得不到调度（饥饿）；且「运行时间」往往无法准确预知。
易错点

① SJF 的最优性有前提：所有作业同时到达。若作业陆续到达，SJF 不一定最优。
② 判断「新到的短作业能否插队」时，一定要看是非抢占还是抢占式：非抢占式要等当前进程运行完；抢占式（SRTN）比较的是剩余时间。

4. 高响应比优先 HRRN

HRRN（Highest Response Ratio Next）：每次调度时计算各就绪作业的响应比，选响应比最高者运行。响应比定义为：

响应比 R = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间 / 要求服务时间
  • 等待时间相同时，服务时间越短，响应比越高 → 照顾短作业；
  • 服务时间相同时，等待时间越长，响应比越高 → 兼顾长作业，避免其饥饿。
关键结论

HRRN 是非抢占式算法，它综合了 FCFS（看等待时间）与 SJF（看服务时间）的优点：既照顾短作业，又不让长作业饿死，是一种折中且较优的算法。其代价是每次调度都要重新计算响应比，有一定开销。

5. 优先级调度

给每个进程分配一个优先级，调度时选择优先级最高的进程运行。同样分非抢占式与抢占式两种；抢占式下，一旦出现更高优先级的进程，立即剥夺当前进程的 CPU。

  • 优先级可以是静态的（创建时确定、不变）或动态的（随等待时间增长而提高，防止饥饿）；
  • 优先级可分为「数大者优先」（如数字越大越优先）或「数小者优先」（如「0 为最高优先级」），做题务必看清题目约定；
  • 缺点：若采用固定优先级，低优先级进程可能长期得不到调度，产生饥饿。
易错点

「优先级」高低的数值方向完全取决于题目定义，不要想当然认为数值越大越优先。另外，通常系统进程优先级高于用户进程，I/O 繁忙型进程优先级常高于 CPU 繁忙型进程（以便尽早启动 I/O、提高并发度）。

6. 时间片轮转 RR

RR（Round Robin）：把就绪队列中的进程按 FCFS 排成队列，每次调度队首进程，让它运行一个时间片；时间片用完（或被阻塞）后，若未完成，则回到就绪队列队尾排队，再取新的队首运行。RR 是抢占式的（由时钟中断剥夺 CPU）。

  • 时间片大小的影响：时间片太大，RR 退化为 FCFS，响应时间变长；时间片太小，进程切换过于频繁，系统开销增大。因此时间片要取一个适中的值。
  • 优点：响应及时、公平，不会饥饿，非常适合分时/交互式系统。
  • 缺点：不区分任务紧急程度；若时间片过小，上下文切换开销大。
RR 计算示例

三个进程 A、B、C 同时在 0 时刻到达，服务时间分别为 4、3、2，时间片 q = 1，采用 RR（时间片到则回队尾）：

执行顺序为：A(0-1) → B(1-2) → C(2-3) → A(3-4) → B(4-5) → C(5-6) → A(6-7) → B(7-8) → A(8-9)。
各进程完成时刻：C 在 6、B 在 8、A 在 9。可见「长作业」被反复放回队尾，完成得晚；这正是 RR 公平但不利于长作业的体现。

7. 多级反馈队列

多级反馈队列（Multilevel Feedback Queue）是综合前述算法优点的最通用调度算法，也是考试的重点。

定义与规则

① 设置多个就绪队列，优先级从第 1 级逐级降低，各队列时间片逐级加倍（队列级别越低、时间片越长）。
② 新进程先进入第 1 级队列队尾，按 FCFS 排队，轮到它时运行一个该级时间片。
③ 若在该级时间片内完成，则撤离；若用完时间片仍未完成，则降到下一级队列队尾；若因 I/O 阻塞，则阻塞结束后仍回到原队列（有的教材设定回第 1 级）。
④ 只有高优先级队列为空时，才调度下一级队列中的进程；若运行过程中有更高优先级的进程到达，则立即抢占，当前进程放回原队列队尾。

关键结论：多级反馈队列的优点

① 对短作业友好：短作业在第 1 级时间片内即可完成，响应快；
② 对长作业也不饿死：长作业会逐级下降，最终获得越来越长的时间片；
③ 兼顾 I/O 繁忙型进程（常在第 1 级获得及时响应）与 CPU 繁忙型进程（下降后获得长时间片）；
④ 因此它兼顾了响应时间与系统效率，是较为理想的通用调度算法。

8. 各算法对比与适用场景

算法是否抢占选择依据优点缺点/易错
FCFS非抢占到达先后公平、简单、不饥饿对短作业不利，平均周转时间可能偏大
SJF / SPF非抢占 / 抢占(SRTN)服务时间最短（抢占看剩余时间）同时到达时平均等待/周转时间最优长作业可能饥饿；运行时间难预知
HRRN非抢占响应比最高兼顾长短作业，避免饥饿每次需重算响应比，有开销
优先级非抢占 / 抢占优先级最高可处理紧急任务固定优先级可能导致低优先级饥饿
时间片轮转 RR抢占时间片到则回队尾响应快、公平、不饥饿时间片过小开销大、过大退化为 FCFS
多级反馈队列抢占多队列+变长时间片兼顾响应与效率，综合最优参数设置复杂
关键结论：谁「不公平/会饥饿」

会导致饥饿的算法：SJF（短作业优先）、固定优先级调度。
不会饥饿的算法：FCFS、HRRN、时间片轮转 RR、多级反馈队列。这是判断题的高频考点。

9. 本节小结与真题问法

记忆口诀

先来先服务（排队）；短作业优先（挑短的、会饿死长的）；高响应比（长短兼顾、不饿）；时间片轮转（公平轮转、分时首选）；多级反馈（综合最优、考试最爱）。

真题典型问法

① 给出作业表（到达时间、服务时间），要求写出某算法的执行顺序并计算平均周转时间、平均带权周转时间。
② 比较 FCFS 与 SJF：SJF 平均周转时间通常更短，但可能使长作业饥饿。
③ 问「哪种算法能得到最小的平均等待时间」→ 在同时到达的前提下，SJF。
④ 问「分时系统最常用的算法」→ 时间片轮转 RR。
⑤ 问「综合性能最好、兼顾长短作业的算法」→ 多级反馈队列。
⑥ 判断「时间片越大越好」→ 错误，时间片过大 RR 退化为 FCFS，过小则切换开销大。

教材原文（王道）

先来先服务算法每次从就绪队列选择最先进入的进程；短作业优先算法选择运行时间最短的进程，在所有作业同时到达时可以获得最小的平均等待时间；高响应比优先算法综合了等待时间与服务时间；时间片轮转算法按时间片轮流调度，适用于分时系统；多级反馈队列算法是综合了上述算法优点的调度算法。
