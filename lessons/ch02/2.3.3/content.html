2.3.3 信号量机制

前述的软件方法与硬件方法，要么实现复杂、容易出错，要么存在「忙等待」而不满足让权等待。1965 年荷兰学者 Dijkstra 提出了一种功能更强、使用更方便的进程同步工具——信号量（Semaphore）机制。它既能用于解决互斥问题，又能用于解决同步问题，是操作系统中最重要的同步工具，也是 408 命题的绝对重点。

定义

信号量是一个用来表示系统中某种资源数量的变量。进程通过两个标准的原语来访问信号量：P 操作（wait）用于申请一个资源，V 操作（signal）用于释放一个资源。所谓原语，就是执行过程不可被中断的操作。

名称说明

P、V 来自荷兰语 passeren（通过）与 vrijgeven（释放）。wait / signal、down / up 是同一对操作的其它叫法。408 中常把「P 操作」写成 wait(S)，「V 操作」写成 signal(S)。

1. 整型信号量

最朴素的信号量就是一个整型变量 S，只能通过原子操作 wait 与 signal 来访问，且这两个操作不可中断：

int S = 1;              // 初始化信号量

void wait(S) {          // P 操作：申请资源
    while (S <= 0);     // 若没有资源，则循环等待（忙等）
    S = S - 1;          // 有资源则占用一个
}

void signal(S) {        // V 操作：释放资源
    S = S + 1;          // 归还一个资源
}
易错点：整型信号量不满足「让权等待」

整型信号量在资源不足时，进程会停留在 while (S <= 0); 上空转（忙等），并不会让出处理机，因此违背让权等待。此外它把「未占有进程」与「资源数量」混为一谈，无法记录到底有多少个进程在等待、是哪些进程在等待。

2. 记录型信号量

为解决忙等问题，引入记录型信号量。它用一个数据结构来记录「剩余资源数」和「等待该资源的进程队列」：

typedef struct {
    int value;              // 剩余资源数
    struct process *L;      // 等待队列（阻塞在该信号量上的进程）
} semaphore;

void wait(semaphore *S) {   // P 操作
    S->value--;
    if (S->value < 0) {     // 说明已无可用资源
        block(S->L);        // 自我阻塞，挂到等待队列（让出处理机）
    }
}

void signal(semaphore *S) { // V 操作
    S->value++;
    if (S->value <= 0) {    // 说明仍有进程在等待
        wakeup(S->L);       // 唤醒等待队列中的第一个进程
    }
}
关键结论：value 的物理意义

对记录型信号量：
① 当 value > 0 时，value 表示当前还可用的资源数量；
② 当 value < 0 时，value 表示等待队列中被阻塞的进程数量（此时值为 -n 表示有 n 个进程在等待）；
③ value 的初值表示系统中该资源的初始数量。

关键结论：为什么记录型信号量满足让权等待

P 操作在资源不足时调用 block 原语，使进程主动阻塞并进入等待队列，从而让出处理机；V 操作释放资源后用 wakeup 唤醒等待进程，使其从阻塞态变为就绪态。因此记录型信号量满足让权等待，不再忙等。判断 P/V 后是否需要 block/wakeup，关键看判断条件的大小关系与等号：wait 用 < 0 判断，signal 用 <= 0 判断。

3. 用信号量实现进程互斥

把信号量初值设为 1（表示只有一个临界资源），即可实现临界区的互斥访问：

semaphore mutex = 1;        // 互斥信号量，初值 1

// 进程 P1
while (true) {
    P(mutex);               // 进入区：申请进入临界区
    critical section;       // 临界区：访问临界资源
    V(mutex);               // 退出区：释放临界区
    remainder section;      // 剩余区
}

// 进程 P2
while (true) {
    P(mutex);
    critical section;
    V(mutex);
    remainder section;
}
关键结论：互斥使用的三个要点

① 初值为 1：一次只允许一个进程进入；
② P、V 必须成对出现：进入区 P，退出区 V；若遗漏 V（只 P 不 V）会导致其它进程永远阻塞；若遗漏 P（只 V 不 P）则互斥失效；
③ P、V 是在同一个进程内成对使用的，且 P(mutex) 与 V(mutex) 之间的临界区代码要尽量短。多个不同的临界资源要用不同的 mutex 信号量分别保护。

易错点：互斥中的 P、V 不能互换位置

若把同一进程内的 P(mutex) 与 V(mutex) 写成「先 V 后 P」或顺序颠倒，会破坏互斥语义（先释放再申请毫无意义）。对于单纯的互斥（只有一个 mutex），V 操作的位置无所谓对错（只要在临界区之后即可），但 P 必须在临界区之前；而涉及同步时 P/V 的顺序则十分关键，详见下一节。

4. 用信号量实现进程同步

同步解决的是「先后次序」问题。若要求操作 A 必须在操作 B 之前完成（前趋关系 A→B），可设置一个初值为 0 的信号量，让 A 结束后执行 V，B 开始前执行 P：

semaphore S = 0;        // 同步信号量，初值 0

// 进程 A：先执行
A();
V(S);                   // A 完成后通知 B：可以开始了

// 进程 B：后执行
P(S);                   // 若 A 未完成则等待
B();
关键结论：同步信号量初值为 0

同步信号量初值为 0，保证「后执行」的进程在「先执行」的进程发出 V 之前，执行 P 时一定会被阻塞。这种「一个进程 V、另一个进程 P」的配对，与互斥中「同一进程内自 P 自 V」形成鲜明对比，是区分同步与互斥的关键。

5. AND 型信号量与信号量集（拓展）

当一次需要申请多个资源时，逐个别 P 可能导致死锁，为此引入两种扩展：

  • AND 型信号量：把多个 P 操作合并为 Swait(S1, S2, …, Sn)，要么一次性分配所有资源，要么一个都不分配，从而避免「各占一部分、互相等待」的死锁。对应的释放为 Ssignal(S1, …, Sn)。
  • 信号量集：进一步允许一次申请多个同类资源，形如 Swait(S1, t1, …)，其中 ti 为需求数量，当且仅当 Si ≥ ti 时才分配。
记忆口诀：AND 型「全拿或全不拿」

AND 型信号量的精髓是「要么都分配，要么都不分配」，用它可以把「分段申请」变成「一次性申请」，从源头消除死锁。

6. 本节小结与真题问法

真题典型问法

① 问「记录型信号量中 value 为负时的含义」→ 表示等待队列中阻塞进程的数目（为其绝对值）。
② 问「哪种信号量满足让权等待」→ 记录型信号量（含 block/wakeup）；整型信号量不满足。
③ 问「互斥信号量与同步信号量的初值」→ 互斥为 1，同步为 0。
④ 给定 P/V 序列判断是否会死锁或破坏互斥 → 抓住「互斥看初值 1、同步看初值 0、P/V 配对」三要素分析。

教材原文（王道）

信号量机制是一种卓有成效的进程同步工具。信号量只能被 wait(S) 和 signal(S) 两个原语访问。记录型信号量在资源不足时会让进程阻塞，从而满足让权等待；用信号量实现互斥时，mutex 的初值为 1，P、V 必须在同一个进程内成对出现；实现同步时，信号量初值为 0，P、V 分别位于两个进程中。

掌握了信号量的定义与 P、V 原语，下一步就是把它们组合起来解决实际的同步与互斥问题——这正是下一节 2.3.4 用信号量实现进程同步与互斥要讨论的内容。
