2.2.2 进程调度的时机、切换与过程、方式

上一节我们知道低级调度（进程调度）是离处理机最近、发生最频繁的一级调度。它虽然频繁，但并不是随时都能发生。本节要解决三个层层递进的问题：什么时候能调度（时机）、调度时系统做了什么（切换与过程）、用什么方式调度（抢占 / 非抢占）。这三块内容高度集中在选择题中，历年被反复考查。

1. 进程调度的时机

所谓进程调度的时机，就是「什么时候会发生进程调度，什么时候绝不能发生」。

1.1 会引起进程调度的情况

可以把引起调度的原因分成两大类：当前进程主动放弃处理机，以及当前进程被动放弃处理机。

类型典型情形说明
主动放弃 进程正常终止 / 异常终止 进程运行结束，处理机当然要让出
主动放弃 进程主动请求阻塞（如请求 I/O、申请资源失败） 进程自身无法继续，进入阻塞态
被动放弃 时间片用完 分时系统中最常见的调度触发点
被动放弃 有更高优先级的进程进入就绪队列 被更高优先级进程抢占
被动放弃 有更紧急的事件需要处理（如 I/O 中断） 系统为响应紧迫事件而剥夺处理机

1.2 不能进行进程调度与切换的情况（高频考点）

下列三种情况不能进行进程调度与切换，必须掌握：

  1. 在处理中断的过程中。中断处理过程复杂，在实现上很难做到进程切换；而且中断处理是系统工作的一部分，逻辑上不属于某一个进程，不应被剥夺处理机资源。
  2. 进程在操作系统内核程序临界区中。进入内核临界区后需要独占式地访问内核共享数据（如就绪队列），加锁后尚未解锁前若发生切换，会破坏这些数据的一致性，因此不能切换。
  3. 在其他需要完全屏蔽中断的原子操作过程中。如加锁、解锁、中断现场保护、恢复现场等原子操作，此时连中断都要屏蔽，更不允许进行进程调度。
易错点 · 内核临界区 vs 普通临界区

要区分「内核程序临界区」与「访问普通临界资源的临界区」。前者访问的是内核数据结构（如就绪队列、进程链表），不能调度与切换；而进程访问普通临界资源（如打印机这类 I/O 设备）时，仍然可以进行调度和切换。很多选择题就靠这一点设陷阱。

关键结论

「内核临界区不能切换」的根本原因是临界资源被独占、加锁未解锁，为保证数据的一致性；而不是因为「在内核态」。内核态本身不是禁止调度的理由。

2. 进程的切换与过程

2.1 什么是进程切换

定义

进程切换是指当前进程让出处理机、由另一进程占用处理机的过程，又称上下文切换（Context Switch）。它需要保存当前进程的现场并恢复新进程的现场。

2.2 进程切换的主要步骤

  1. 保存当前进程的处理机上下文（程序计数器 PC、程序状态字 PSW、各通用寄存器等）到其 PCB 或内核栈中。
  2. 更新 PCB 中的信息，如修改进程状态、把 PCB 保存到相应的队列（就绪队列、阻塞队列等）。
  3. 把当前进程的 PCB 插入相应队列（例如时间片用完则插入就绪队列尾部）。
  4. 从就绪队列中选择另一个进程，并更新其 PCB（将其从队列中移出，置为运行态）。
  5. 切换内存管理相关的数据结构（如切换页表、刷新快表 TLB、更新页目录等）。
  6. 恢复被选中进程的处理机上下文，使其从断点继续运行。

2.3 进程调度与进程切换的区别

辨析

进程调度解决的是「把处理机分配给哪一个进程」的决策问题；进程切换解决的是「从一个进程实际交接到另一个进程」的动作问题。调度是切换的前提，切换是调度决策的执行。

易错点

调度与切换的次数不一定相等：发生调度但「选中的进程还是原进程」时，就不需要真正切换；而切换一定会带来系统开销（保存/恢复现场、切换页表、刷新 TLB 等）。因此进程切换是有代价的，频繁切换会降低系统效率。

3. 进程调度的方式

按「是否允许剥夺当前进程的处理机」，进程调度方式分为非抢占式与抢占式两种。

3.1 非抢占式（非剥夺方式）

  • 特点：只允许进程主动放弃处理机（运行完毕或主动阻塞）。一旦处理机分配给某进程，就一直让它运行下去，直到它完成或阻塞，才发生调度。
  • 优点：实现简单，系统开销小。
  • 缺点：难以满足紧迫任务的要求，无法及时响应，可能导致长作业一直占用处理机。
  • 适用：早期的批处理系统。

3.2 抢占式（剥夺方式）

  • 特点：允许调度程序根据某种原则剥夺当前进程的处理机，把它重新分配给另一个进程。
  • 优点：能防止单一进程长时间独占处理机，可及时响应紧迫任务，便于实现「优先权」「短进程优先」「时间片轮转」等策略。
  • 缺点：实现复杂，调度开销相对较大。
  • 适用：分时系统、实时系统。
抢占遵循的原则

① 优先权原则：更高优先级的进程可以抢占当前进程的处理机。

② 短进程优先原则：新到达的短进程可抢占当前长进程的处理机。

③ 时间片原则：当前进程的时间片用完后被剥夺处理机（时间片轮转）。

其中「时间片原则」的抢占必须有时钟中断等硬件支持。

3.3 两种方式的对比

对比项非抢占式抢占式
处理机能否被剥夺不能能
调度触发仅进程完成或阻塞时完成/阻塞/时间片到/被抢占时
系统开销小较大
响应及时性差好
典型系统批处理系统分时系统、实时系统

4. 调度器与闲逛进程

内核中负责上述调度工作的那部分程序称为调度程序（调度器，Scheduler），它是操作系统内核的一部分，其核心任务是按策略选择就绪进程并把处理机分配给它。

当系统中没有任何就绪进程时，处理机是否就空闲了呢？现代操作系统会运行一个闲逛进程（Idle Process，空闲进程）：它是内核中优先级最低的进程，当没有其他就绪进程时被调度执行。它有两点作用：一是避免处理机「空转」而浪费时钟中断，二是简化调度逻辑（任何时候总有进程运行）。

记忆口诀

调度时机：「主动让权 + 被动剥夺」。主动：完成、阻塞；被动：时间片到、被更高优先级抢占、更紧迫事件。

不能切换三种情况：中断处理中、内核临界区中、原子操作中（口诀「中、界、原」）。

切换过程：「存现场 → 改 PCB → 入队 → 选进程 → 换页表 → 复现场」。

两种方式：非抢占「不夺机」、抢占「可夺机」，时钟中断撑起时间片抢占。

真题典型问法

① 问「进程在操作系统的内核临界区中可以发生进程调度吗」→ 不可以（访问内核共享数据结构，加锁未解锁）。

② 问「时间片用完后引起的调度属于抢占式还是非抢占式」→ 属于抢占式（时间片原则）。

③ 问「进程调度与进程切换的关系/开销」→ 调度是决策、切换是执行，切换有开销；调度不一定引起切换。

④ 问「哪种操作系统适合抢占式调度」→ 分时系统、实时系统；非抢占式多用于批处理系统。

教材原文（王道）

不能进行进程调度与切换的情况有：在处理中断的过程中；进程在操作系统内核程序临界区中；其他需要完全屏蔽中断的原子操作过程中。进程切换是指一个进程让出处理机，由另一个进程占用处理机的过程，进程切换是在内核的支持下实现的，是有代价的。
