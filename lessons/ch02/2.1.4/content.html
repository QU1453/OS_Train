1. 什么是进程通信

系统中的多个进程可以并发执行，但它们往往需要协作完成同一项任务：例如两个进程要共享一段中间结果，或者一个进程要把计算结果交给另一个进程。这种进程之间的信息交换，就称为进程通信（Inter-Process Communication, IPC）。

定义

进程通信是指进程之间的信息交换。由于各进程拥有独立的地址空间，一个进程不能直接访问另一个进程的地址空间，因此必须借助操作系统提供的通信机制来交换数据。

进程通信是「进程同步」的一种高级形式：进程同步（如 PV 操作）主要解决进程推进次序的协调问题，而进程通信则着眼于进程之间大批量数据的传递。王道教材把进程通信归纳为三大类：共享存储（共享内存）、消息传递、管道通信。

通信方式核心思想是否有中间实体 / 共享空间是否需要用户自行互斥同步
共享存储 划出一块共享空间，双方直接读写 有共享存储区 需要（对共享区的访问必须互斥）
消息传递 以「消息」为单位交换数据 无共享空间（经内核/信箱中转） 由系统保证，用户一般无需处理
管道通信 通过一个共享的 pipe 文件（缓冲区）读写 有管道缓冲区 由系统保证读写同步

2. 共享存储（共享内存）

共享存储方式的思想是：操作系统在内存中划出一块区域，作为共享空间，需要通信的进程把这块共享空间映射到自己的地址空间中，就可以像访问本地内存一样直接读写其中的数据。

按照共享空间的粒度，可进一步分为两种：

  • 低级通信方式——基于数据结构：把共享空间组织成某种数据结构（如共享数组、共享队列），进程通过该结构交换数据。这种方式速度慢、能传递的数据量小、使用受限。
  • 高级通信方式——基于存储区：在内存中开辟一整块共享存储区，进程按地址访问。速度快、数据量大、使用灵活，是最常用的共享存储形式。
易错点

共享存储并不是「随便读写」：进程之间存在一块可直接访问的共享空间，但对该共享空间的访问必须是互斥的。也就是说，共享存储方式需要进程自己使用同步互斥工具（如 PV 操作）来保证不会出现多个进程同时读写、导致数据不一致的问题。这是共享存储与消息传递、管道最大的不同。

关键结论

共享存储方式的两个前提：① 操作系统提供共享空间（存储区）；② 进程对该空间的读写必须互斥（否则需要用户引入互斥信号量）。共享存储不涉及数据的复制（直接读写），因此是三种方式中速度最快的。

3. 消息传递

如果两个进程之间不存在共享空间，就无法使用共享存储方式。此时可采用消息传递方式：进程间的数据交换以格式化的消息（Message）为单位，消息中既包含数据，也可能包含消息头和类型。

消息传递是最广泛使用的一种进程通信方式，它可分为两种：

3.1 直接通信方式

发送进程直接把消息发送给目标进程，消息被挂到接收进程的消息缓冲队列上；接收进程从自己的消息缓冲队列中取出消息。常用的两条原语是：

send(Receiver, message);    // 发送一个消息给 Receiver
receive(Sender, message);   // 接收来自 Sender 的消息

直接通信中，通信双方必须显式地指明对方的名字（发送方写接收者、接收方写发送者），因此又称「一对一」的消息传递。

3.2 间接通信方式

发送进程把消息发送给一个中间实体，通常称为信箱（Mailbox）；接收进程从这个信箱中取走消息。因此间接通信又称信箱通信。常用的两条原语是：

send(mailbox, message);     // 把消息发送到指定信箱
receive(mailbox, message);  // 从指定信箱取出消息

间接通信中，进程之间不直接指定对方，而是通过共享一个信箱来交换消息，因此 send 和 receive 中的进程名可以省略，一个信箱可以被多个进程共享，灵活性和通用性更强，是更常用的消息传递形式。

关键结论：直接通信 vs 间接通信

① 直接通信：消息直接挂到接收进程的消息缓冲队列，send/receive 中要写明收发进程；② 间接通信：消息先发到信箱这个中间实体，再由接收进程取走，send/receive 中指明的是信箱而非进程。两者的核心区别在于是否存在中间实体（信箱）。

3.3 关于消息缓冲队列的补充

直接通信中被挂入的「消息缓冲队列」，其本质是接收进程的一个缓冲区。发送进程与接收进程围绕这个缓冲区一「送」一「取」，恰好构成一个生产者—消费者问题：当缓冲区中没有消息时，接收进程必须等待；当缓冲区已满时，发送进程必须等待。因此消息传递方式虽然由系统负责同步，但其内部机制往往同样需要借助同步互斥手段来保证消息的有序收发。

此外，消息传递方式的一个显著优点是：进程之间无需共享地址空间，只要借助操作系统提供的 send / receive 原语即可交换数据，因此它非常适合分布式系统中不同机器上进程之间的通信；这是共享存储方式所不具备的。

最后要区分「共享存储」与「消息传递」的根本前提：共享存储要求通信双方能访问同一块内存，而消息传递只要求双方能调用内核提供的通信原语，对内存布局没有要求。正因如此，在微内核结构与网络编程中，消息传递往往是首选的进程通信方式。

4. 管道通信

定义

管道（pipe）是指用于连接一个读进程和一个写进程，以实现它们之间通信的一个共享文件，又称 pipe 文件。从本质上看，管道是内存中一个大小固定的缓冲区。

为了协调通信双方的读写，管道机制必须提供三方面的支持：互斥（保证读写不同时进行）、同步（写满则等待、读空则等待）、确定对方存在（确认读写进程是否已就绪）。

管道通信有以下几个鲜明的特点：

  • 半双工：某一时刻数据只能单向传输。若要实现双向同时通信，必须建立两个管道。
  • 写满则阻塞写进程：当管道（缓冲区）被写满时，写进程会被阻塞，等待读进程取走数据后再继续写。
  • 读空则阻塞读进程：当管道为空时，读进程会被阻塞，等待写进程写入数据后再继续读。
  • 数据一旦被读出就丢弃：管道中的数据被读进程读走后即被丢弃，因此读进程最多只能有一个（多个读进程会争抢数据导致混乱）。
记忆口诀

管道通信记「三特点」：半双工、写满/读空则阻塞、读完即丢。
再补一句：管道是共享文件（pipe 文件），本质是内存缓冲区。

5. 本节小结与真题问法

记忆口诀

三大方式：共享存储、消息传递、管道通信（「共消管」）。
共享存储：有共享区，需互斥，分低级（数据结构）/ 高级（存储区），速度最快。
消息传递：无共享区，分直接（挂到接收进程缓冲队列）/ 间接（发到信箱），system 保证同步。
管道：共享 pipe 文件，半双工，写满阻塞写、读空阻塞读，读出即丢弃，读进程最多一个。

真题典型问法

① 问「进程通信的方式有哪些」→ 答共享存储、消息传递、管道通信。
② 问「哪种通信方式需要进程自己实现互斥」→ 答共享存储（消息传递与管道的同步由系统处理）。
③ 问「直接通信与间接通信的区别」→ 关键在于是否存在中间实体（信箱）；间接通信又称信箱通信。

④ 问「管道的特性」→ 半双工、写满/读空则阻塞、数据读出即丢弃、读进程最多一个。
⑤ 给若干说法判断对错，常见错误项：把共享存储说成「无需同步」、把管道说成「全双工」、把间接通信的 send 说成「必须写明接收进程名」。

教材原文（王道）

进程通信是指进程之间的信息交换。常用的进程通信方式有三类：共享存储、消息传递和管道通信。共享存储方式下，进程对共享空间的访问必须是互斥的；消息传递方式以格式化的消息为单位交换数据，分为直接通信方式和间接通信方式；管道通信通过一个共享的 pipe 文件实现读写进程之间的通信。
